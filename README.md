# CareSignal

A discharge-planning AI agent for hospital care teams. It finds patients at high risk of
30-day readmission, explains what is driving the risk, checks their medication list for
interactions, and answers questions about the cohort in plain language.

> **Synthetic data only.** Every patient is generated by a seeded random process. This is a
> working reference application, not a certified medical device; see [Before real use](#before-real-use).

## How it fits together

```
 React + TypeScript UI  ──►  FastAPI  ──►  Claude agent (tool loop)
        (web/)               (api.py)          (agent.py)
                                │                  │  MCP (stdio)
                                │                  ▼
                                └──────►  MCP server (mcp_server.py)
                                          6 clinical tools over service.py
                                                   │
                         pandas cohort  +  PyTorch risk model (model.py)
                                                   │
                              R validation (r/analysis.R)   AWS CDK (infra/)
```

| Piece | Tech | Where |
| --- | --- | --- |
| Synthetic cohort, feature pipeline | NumPy, pandas | `caresignal/data.py`, `caresignal/model.py` |
| Readmission risk model + per-patient drivers | PyTorch | `caresignal/model.py` |
| Clinical tools (patients, risk, interactions, cohort stats) | MCP server | `caresignal/mcp_server.py` |
| Agent | Claude (`claude-opus-5-5`) via the Anthropic SDK tool runner, as an MCP client; Amazon Bedrock and Google Gemini are switchable providers | `caresignal/agent.py` |
| REST API | FastAPI | `caresignal/api.py` |
| Web app | TypeScript, React, Vite | `web/` |
| Independent model validation | R (base only) | `r/analysis.R` |
| Deployment | AWS CDK (TypeScript): Fargate + ALB + Bedrock | `infra/`, `Dockerfile` |

The agent holds no clinical logic of its own: every fact it states comes from an MCP tool
call. The same server therefore works unchanged in Claude Desktop or Claude Code:

```json
{ "mcpServers": { "caresignal": { "command": "python", "args": ["-m", "caresignal.mcp_server"], "cwd": "/path/to/caresignal" } } }
```

## Run it

```bash
pip install -r requirements-dev.txt
```

```bash
python -m caresignal.model        # generate cohort + train (about 10 s on CPU) -> artifacts/
```

```bash
npm --prefix web install && npm --prefix web run build
```

```bash
export ANTHROPIC_API_KEY=...      # needed only for the chat panel
uvicorn caresignal.api:app --port 8000
```

To use Google Gemini instead (it has a free tier; create a key in Google AI Studio):

```bash
export CARESIGNAL_PROVIDER=gemini GEMINI_API_KEY=...
uvicorn caresignal.api:app --port 8000
```

The Gemini path uses Google's OpenAI-compatible endpoint and defaults to
`gemini-3.5-flash-lite` (override with `CARESIGNAL_GEMINI_MODEL`). Free-tier Gemini is rate
limited and its larger models are sometimes unavailable under load. Check Google's
free-tier data terms before sending anything other than synthetic data.

Open http://localhost:8000. Without an API key the patient list, risk drivers and
medication checks all work; the chat panel reports that the LLM is not configured.

Other entry points:

```bash
python -m caresignal.agent        # terminal chat with the agent
```

```bash
Rscript r/analysis.R              # writes artifacts/r_validation.md
```

```bash
pytest                            # model, service, MCP-over-stdio, REST API, agent loop
```

For UI development run `npm --prefix web run dev` (proxies `/api` to port 8000).

## The model

A small MLP trained on 17 features (age, prior admissions, length of stay, Charlson index,
labs, comorbidities, living situation, discharge disposition). On the held-out test split
of the default cohort (6,000 patients, 18% readmitted):

- AUROC **0.76**, Brier score 0.127
- The R script fits a plain logistic regression on the same split and scores **0.77**. The
  neural net does not beat the simple baseline on this data; it is here to show the
  PyTorch serving path, and the R report makes that comparison visible on every run.

"Drivers" are occlusion attributions: how many points the predicted risk moves when one
feature is replaced by the cohort average.

## Deploy to AWS

```bash
cd infra && npm install && npx cdk bootstrap && npx cdk deploy
```

This builds the Docker image and runs it on ECS Fargate in private subnets behind a public
Application Load Balancer. The container sets `CARESIGNAL_PROVIDER=bedrock`, so the agent
calls Claude through Amazon Bedrock using the task's IAM role (no API key to store). Your
account needs Bedrock model access for the Claude model in that region. `npx cdk destroy`
removes everything.

## Before real use

This repository deliberately stops short of things a deployment touching real patient
data must have:

- **Authentication and authorisation.** The API has none; the stack's load balancer is
  public HTTP. Add TLS, SSO and role-based access before exposing it.
- **Audit logging** of who viewed which patient and what the agent was asked.
- **A real data source** (EHR/FHIR) in place of the synthetic cohort, under a BAA with
  every vendor in the path (cloud and LLM provider).
- **A licensed drug-interaction database.** `service.py` holds a dozen illustrative pairs.
- **Clinical validation** of the model on the target population, with calibration and
  subgroup-fairness review, plus whatever regulatory review applies.
